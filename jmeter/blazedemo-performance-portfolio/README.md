# BlazeDemo Performance & QA Testing Portfolio

**Author:** Mandla Qhomane

This project shows a full round of QA testing on [BlazeDemo](https://blazedemo.com), a public flight-booking demo site. It covers planning, writing test cases, running performance tests, finding and reporting bugs, and closing out the testing round — following the standard steps testing teams use in the real world (STLC).

## What This Project Shows
- How to plan a testing effort before writing any tests
- How to write clear, professional test cases
- How to run performance tests using JMeter (checking speed, load limits, and stability)
- How to spot and write up real bugs, the way a QA tester would report them to a dev team
- How to close out a testing round with a summary of what was found

## Key Results
| What Was Tested | Result |
|---|---|
| Full booking process (search → pick flight → pay) | Works correctly, finishes in under 3 seconds |
| How many people the site can handle at once | Starts struggling around 160–165 people using it at the same time |
| Site behavior over a long period (1 hour of steady use) | Stayed stable, no slowdowns over time |
| Site behavior when tricked with a bad/incomplete request | Found a real bug — see `bug-reports/` |

**2 bugs found and documented** — see `bug-reports/README.md` for the full list.

## How This Project Is Organized
| Folder | What's In It |
|---|---|
| `docs/` | The overall testing plan and requirements |
| `test-plans/` | The actual JMeter test file and test data used |
| `test-cases/` | Step-by-step write-ups of each test (TC1–TC6) |
| `test-results/` | Raw results and graphs from running the tests |
| `test-reports/` | The full HTML report generated by JMeter |
| `bug-reports/` | Detailed write-ups of every bug found |
| `test-closure/` | The final summary report for the whole testing round |
| `ci-cd/` | Notes on how these tests can run automatically |

## Where to Start
1. Read `docs/01-test-strategy.md` for the overall plan.
2. Look through `test-cases/` to see how each test was designed.
3. Check `bug-reports/` to see real bugs found and how they were documented.
4. Read `test-closure/TEST_CLOSURE_REPORT.md` for the big-picture summary.
